## 1. What was learned from each reference

### 1.1 monkeytypegame/monkeytype

**Read:** `frontend/src/ts/input/listeners/input.ts`, `handlers/insert-text.ts`,
`handlers/delete.ts`, `handlers/before-delete.ts`, `test/test-words.ts`,
`test/caret.ts`, `elements/caret.ts`, `test/test-ui.ts`, `utils/numbers.ts`.

**Input model:** Monkeytype uses a hidden `<textarea>` with a leading sentinel space
trick: `el.value = " " + value`. This lets it detect backspace-at-word-start (the
sentinel disappears) without fighting mobile keyboards or IME. Events flow through
`beforeinput` (gatekeeper: block excess length, block backspace into correct words) →
`input` (process character, evaluate correctness, log event, update DOM). Characters
emit one at a time via `emulateInsertText` to chunk multi-char IME input. DOM rendering
is coalesced via `requestDebouncedAnimationFrame` keyed by string ID, so rapid bursts
cause only one layout per frame.

**Character states:** Four DOM states via CSS classes on `<letter>` elements: untyped
(no class), `correct`, `incorrect`, `incorrect extra` (beyond target word length). Word
elements carry `.active`, `.typed`, `.error`.

**Caret positioning:** Monkeytype reads `getOffsetLeft()`, `getOffsetTop()`,
`getOffsetWidth()` from letter DOM elements on every caret move, inside a debounced rAF.
Smooth caret uses anime.js with 85–150ms transitions on `left` and `top` properties.

**What we take:** The input-model separation (capture in handler, render in rAF loop,
drain a queue). The gatekeeper pattern in `beforeinput` for blocking invalid deletes.
The correction semantics: backspace into a correctly typed previous word is blocked.

**What we reject:** (1) The live DOM layout reads for caret — we cache glyph offsets
into a `Float32Array` once per drill and never read layout during the hot path.
(2) Animating `left`/`top` properties on the caret — we use `transform: translate3d()`
only. (3) Their WPM formula — Monkeytype uses an all-or-nothing word penalty where one
typo in a 12-letter word zeroes the whole word's contribution to Net WPM; we use uWPM
which measures only unbroken clean stretches and excludes correction time from both
numerator and denominator. (4) anime.js — we have no animation library budget.

### 1.2 microsoft/vscode-extension-samples

**Read:** `webview-view-sample/` (all files), `webview-sample/src/extension.ts`,
`custom-editor-sample/src/pawDrawEditor.ts` (for `retainContextWhenHidden` placement).

**Provider pattern:** `WebviewViewProvider` implements `resolveWebviewView()`. View is
declared in `package.json` under `contributes.views` with `"type": "webview"` in a
named container. The provider is registered via
`window.registerWebviewViewProvider(viewId, provider, options)`.

**CSP and nonces:** HTML is generated by a `_getHtmlForWebview(webview)` method.
A 32-char random nonce is generated per resolve. CSP is a meta tag:
`default-src 'none'; style-src ${webview.cspSource} 'nonce-${nonce}'; script-src 'nonce-${nonce}'`.
We add `font-src ${webview.cspSource}; media-src 'none'; connect-src 'none'`.

**`localResourceRoots`:** Set on `webviewView.webview.options` inside `resolveWebviewView`,
limited to `[vscode.Uri.joinPath(extensionUri, 'dist')]`. Asset URIs are created via
`webview.asWebviewUri()`.

**Message passing:** Host → webview via `webview.postMessage(msg)`. Webview → host via
`acquireVsCodeApi().postMessage(msg)`. `acquireVsCodeApi()` may only be called once.

**What we take:** The HTML generation pattern with nonce substitution. The CSP string
format. The `localResourceRoots` to `dist/` only. The message protocol shape.

**What we reject:** The Webview UI Toolkit (not present in samples; confirmed absent).
The vscode.css theme variable passthrough (we use our own palette exclusively, never
`--vscode-*` variables). No state via `vscode.getState()`/`setState()` — our webview
never touches disk and state flows through the host-side protocol.

**Critical finding:** `retainContextWhenHidden` must be passed as the 3rd argument to
`registerWebviewViewProvider`, not in `webviewView.webview.options`. The architecture
docs describe it alongside `enableScripts` which is misleading — fix in the same change.

### 1.3 disler/claude-code-hooks-mastery

**Read:** `.claude/settings.json`, `.claude/hooks/user_prompt_submit.py`,
`.claude/hooks/stop.py`, `.claude/hooks/subagent_stop.py`,
`.claude/hooks/notification.py`, `.claude/hooks/session_start.py`,
`ai_docs/claude_code_hooks_docs.md`, `ai_docs/claude_code_hooks_getting_started.md`.

**Hook registration:** In `~/.claude/settings.json` (user global) or
`.claude/settings.json` (project), under `"hooks"`. Each event name maps to an array of
matcher entries: `[{ "matcher": "...", "hooks": [{ "type": "command", "command": "..." }] }]`.
For events that don't use matchers (`UserPromptSubmit`, `Stop`, `SubagentStop`), the
matcher field can be omitted. The repo confirms all five event names our spec uses
(`SessionStart`, `UserPromptSubmit`, `Notification`, `Stop`, `SubagentStop`) are correct.

**Payload shapes:** All payloads arrive on stdin as JSON with **snake_case** field names:
`session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`, plus
event-specific fields (`prompt` for UserPromptSubmit, `stop_hook_active` for Stop/
SubagentStop, `notification_type` and `message` for Notification, `source` and `model`
for SessionStart, `agent_id` and `agent_transcript_path` for SubagentStop).

**What we take:** The exact event names. The registration JSON structure. The pattern of
reading stdin as a complete JSON blob, parsing once, and extracting fields. The
convention that hooks exit 0 and print nothing in all cases.

**What we reject:** Their Python/uv approach — our hook is a single zero-dependency
CommonJS file. Their complex TTS and logging — our hook writes one line of JSON to a
local socket and exits.

### 1.4 eclipse/openvsx (and ovsx CLI)

**Read:** `cli/src/publish.ts`, `cli/src/main.ts`, `cli/src/check-license.ts`,
`server/src/main/java/org/eclipse/openvsx/ExtensionValidator.java`,
`server/src/main/java/org/eclipse/openvsx/publish/PublishExtensionVersionHandler.java`.

**Publishing requirements:** `engines.vscode: ^1.93.0` is supported — Open VSX imposes
no restriction on engine ranges. A `LICENSE` file is mandatory. Icons must be PNG, not
SVG. The maximum VSIX size is 512 MB (server default). Proposed APIs are **not**
rejected by Open VSX itself, but `vsce` refuses to package them without
`--allow-proposed-apis`. Since our spec forbids proposed APIs, this is moot.

**What we take:** The confirmation that `^1.93.0` and no proposed APIs is the correct
configuration for cross-publishing to both registries. The `ovsx publish <file.vsix>`
pattern for pre-built artifacts. The license requirement — ship a root `LICENSE` file.

**What we reject:** Nothing — this was a verification exercise.

## 2. Discrepancies found between specs and current API reality

### D1: `retainContextWhenHidden` placement (ARCHITECTURE.md §2, DESIGN-SYSTEM.md §9.1)

**Spec says:** Listed alongside `enableScripts: true` and `localResourceRoots` under
webview options in `resolveWebviewView`.

**Reality:** `retainContextWhenHidden` is NOT a property of `WebviewOptions`. For a
`WebviewViewProvider`, it must be passed as the 3rd argument to
`window.registerWebviewViewProvider(id, provider, { webviewOptions: { retainContextWhenHidden: true } })`.
`enableScripts` and `localResourceRoots` are set on `webviewView.webview.options` inside
`resolveWebviewView`.

**Fix:** Correct ARCHITECTURE.md to separate the two. Implementation will place it
correctly.

### D2: Claude Code hook payload field casing (SPEC.md §4.2, ARCHITECTURE.md §6)

**Spec says:** IPC frame example uses `sessionId` (camelCase).

**Reality:** Claude Code sends `session_id` (snake_case) on stdin. All payload fields
are snake_case: `session_id`, `transcript_path`, `hook_event_name`, `permission_mode`,
`stop_hook_active`, `agent_id`, `agent_transcript_path`.

**Fix:** `hook.cjs` reads `payload.session_id` and maps to our IPC frame's `sessionId`.
The IPC frame format (our internal protocol) can remain camelCase. Update SPEC.md to
note the mapping.

### D3: `TextDocumentChangeReason` check syntax (SPEC.md §4.1)

**Spec says:** `reason === TextDocumentChangeReason.Undo|Redo`

**Reality:** This is ambiguous and would be interpreted as bitwise OR (`1 | 2 = 3`) in
code, which never matches. The correct check is:
`e.reason !== TextDocumentChangeReason.Undo && e.reason !== TextDocumentChangeReason.Redo`.
For normal edits, `reason` is `undefined`.

**Fix:** Correct SPEC.md. Implementation uses the proper two-branch check.

### D4: `ColorThemeKind.HighContrastLight` not handled (DESIGN-SYSTEM.md §2)

**Spec says:** "High-contrast themes get the dark palette with `--ink-050` → `#FFFFFF`."

**Reality:** VS Code has `ColorThemeKind.HighContrastLight = 4` (since 1.65). Applying
a dark background in a light high-contrast theme is a usability violation.

**Fix:** Map `Light` and `HighContrastLight` → light palette base, then apply HC
overrides (`--ink-050 → #000000`, crisp hairlines to `--ink-200`). Map `Dark` and
`HighContrast` → dark palette base with HC overrides (`--ink-050 → #FFFFFF`,
`--ink-400 → #6E6A64`). Update DESIGN-SYSTEM.md.

### D5: `Stop` does not fire on user interrupt (Claude Code hooks)

**Spec says:** Relies on `Stop` for task-end.

**Reality:** If the user presses Ctrl+C to cancel a Claude Code turn, the `Stop` hook
does NOT fire. The 15-minute ceiling fallback and the transcript watcher (4s of quiet)
handle this, but it should be documented.

**Fix:** Note this in SPEC.md §4.2 and in the implementation comments. The 15-minute
ceiling and transcript watcher already serve as fallbacks.

### D6: `TaskEndEvent` has no `exitCode`

**Spec says:** Uses `tasks.onDidEndTask` for task lifecycle.

**Reality:** `TaskEndEvent` contains only `execution: TaskExecution`, no `exitCode`. To
get exit codes, use `tasks.onDidEndTaskProcess` (`TaskProcessEndEvent.exitCode`).

**Fix:** For Dwell's purposes (binary running/idle detection), `onDidEndTask` is
sufficient — we don't need exit codes. No spec change required.

### D7: Terminal shell execution `commandLine` is an object, not a string

**Spec says:** Implies command line is available for filtering.

**Reality:** `execution.commandLine` is a `TerminalShellExecutionCommandLine` object
with `.value: string`, `.isTrusted: boolean`, `.confidence: enum`. Access via
`execution.commandLine.value`.

**Fix:** Implementation uses `.commandLine.value`. Minor, no spec change needed.

## 3. Open questions the specs did not settle

### OPEN: Multiple editor windows and the IPC server

The spec notes this as "OPEN" in ARCHITECTURE.md §6. When multiple VS Code windows are
open, only one can bind the socket.

**Recommendation:** First listener wins. Later windows skip the IPC server and rely on
the transcript watcher (`claudeTranscript.ts`, priority 80). The hook writes to the
socket regardless — the first window receives it. This is simple, correct, and avoids
rebroadcast complexity. Add a log line: `"dwell: IPC server already bound, using
transcript watcher"`.

### OPEN: `fsWatch.ts` signal — what files to watch, what threshold

The spec lists `createFileSystemWatcher` as priority 20 but doesn't specify which glob
patterns, which files to exclude, or what constitutes a qualifying burst.

**Recommendation:** Watch `**/*` excluding `node_modules`, `.git`, `dist`, `build`. A
qualifying event is a file creation or modification where the file is not currently open
in an editor. Require ≥3 such events in 3 seconds. This is the lowest-priority signal
and exists only as a last-resort fallback. Keep it simple.

### OPEN: Corpus item count per tier

The spec says "~400 authored drill items" total and gives approximate counts per tier
(80, 70, 70, 70, 60, 50 = 400). For v1 MVP, we can ship with fewer — say 20 per tier
(120 total) — and expand later.

**Recommendation:** Ship v1 with ≥20 items per tier (≥120 total). All must pass the
corpus linter. More is better but should not block the first working version.

### OPEN: Wick's height formula — what "running median" means

The spec says Wick's height is "elapsed time of the current agent task against a running
median of recent tasks." It doesn't specify the window size or how to compute the median
with zero or few samples.

**Recommendation:** Median of the last 20 completed agent task durations. With <3
samples, use a default of 120 seconds. Height = `clamp(elapsed / median, 0.1, 1.0)` ×
max wick height (40px - 8px flame = 32px usable).

### OPEN: `hostProbe.ts` — what to probe for

The spec says "feature-detect any host-specific agent API via `vscode.extensions.all`
and the global namespace." It doesn't say what to look for.

**Recommendation:** At activation, check for extensions with IDs matching known agent
patterns (`github.copilot`, `cline.*`, `anthropic.*`). If found, check if they expose
any activation-event APIs or contribute commands that indicate agent state. For v1,
log what we find and proceed with the standard signals. This is a stub that becomes
useful when a host actually exposes an API.

### OPEN: Tier 5 structural recall scoring

The spec says "passes on structural recall, not character-exactness." It doesn't define
the scoring function.

**Recommendation:** For each required section in the `sections` array, check if a
line starting with that section name appears in the typed output. For each required
key term in `keyTerms`, check if it appears as a substring. Score = (matched sections +
matched terms) / (total sections + total terms). Pass threshold: ≥ 0.75. uWPM is
measured and displayed but does not gate the pass. This is a pure function in
`packages/core/src/scoring.ts`.

### OPEN: Tier 6 cold scoring — "structure coverage"

Similar to Tier 5: check for the presence of `Goal`, `Context`/`Constraints`, `Done`
sections. Score on structure, not content.

**Recommendation:** Same section-presence check as Tier 5. Latency-to-first-keystroke
is the primary displayed metric. Speed is shown but gates nothing. A "pass" requires
≥ 3 of 4 sections present and non-empty.

### OPEN: First-run detection mechanism

The spec says "opens itself once, immediately after install." Doesn't specify how to
detect first run.

**Recommendation:** Check `context.globalState.get('dwell.firstRunDone')`. If absent,
reveal the panel with `reason: 'first-run'`, then set the flag. Simple and reliable.

### OPEN: The "detect/fsWatch.ts" signal is in TREE.md but not in ARCHITECTURE.md's signal list

TREE.md lists a `detect/fsWatch.ts` file but the ARCHITECTURE.md signal priority list
doesn't include it.

**Recommendation:** The rules in `40-host-detection.md` DO list `fs-watch 20`. Include
it as specified. TREE.md wins over ARCHITECTURE.md omission here.

## 4. Milestone sequence

### M0: Skeleton and harness (no logic, proves the structure works)

- Initialize pnpm workspace with all 5 packages and the harness app.
- Create `tsconfig.base.json` and per-package configs.
- Set up esbuild for `packages/core`, `packages/webview`, `packages/extension`.
- Add the lint rule that fails `packages/core` on `vscode` or DOM imports.
- `apps/harness` serves via Vite and renders "hello" in a `<div>`.
- `pnpm -r build` produces zero errors.

**Proof:** `pnpm -r build` exits 0. `pnpm --filter harness dev` serves a page.
The lint rule rejects a test file that imports `vscode` in `packages/core`.

### M1: Core engine and scoring (pure logic, zero DOM)

- Implement `types.ts` (message protocol union, glyph states, tier definitions).
- Implement `engine.ts` (drill state machine: load drill, process keystroke, advance
  cursor, track glyph states pending/struck/missed/corrected).
- Implement `scoring.ts` (uWPM over clean stretches, latency, longest clean run).
- Implement `tiers.ts` (6 tier definitions, targets, 3-consecutive unlock rule).
- Implement `offer-governor.ts` (all interruption rules as pure functions).
- Write initial corpus for all 6 tiers (≥20 items each), plus corpus linter.
- Full vitest test suite mirroring src/ 1:1.

**Proof:** `pnpm --filter core test` passes with 100% of scoring edge cases, tier FSM
transitions, offer governor truth table, and corpus linter. Zero imports of `vscode` or
DOM types in `packages/core`.

### M2: Webview surface (the thing you see and type into)

- `packages/webview/src/main.ts`: boot, message listener, single rAF loop, keystroke
  queue drain.
- `render/glyphs.ts`: build span track once per drill, cache offsets in `Float32Array`.
- `render/caret.ts`: `will-change: transform` only, `translate3d()` movement.
- `render/wick.ts`: flame geometry, three-sine sway, burn-down.
- `render/trace.ts`: 20 hairlines in the idle screen.
- `styles/tokens.css`: the full palette, dark and light, as custom properties.
- `styles/panel.css`: layout using the 4px scale. Zero colour literals.
- `index.html`: CSP shell with nonce placeholders.
- Bundle fonts (iA Writer Quattro S + IBM Plex Mono woff2) into `assets/fonts/`.
- Wire `apps/harness` to mount the real webview with mock host controls.

**Proof:** `pnpm --filter harness dev` shows the idle screen with Wick, trace, and
tier/number line. Theme toggle works (dark/light/HC). Typing a drill produces lit
glyphs, caret movement, error states, and scrolling. Reduced-motion toggle zeroes all
durations and stops the flame.

### M3: Sound

- `audio/keys.ts`: WebAudio synthesis per the spec — noise burst + sine body, the
  four-note set, inverse-velocity gain, Enter/Backspace variants.
- Master chain: compressor (−24, 4:1), lowpass 7kHz.
- Lazy `AudioContext` on first keystroke, `suspend()` on hide.
- Sound toggle wired to the metric strip, state persisted via `pref:set`.

**Proof:** Typing in the harness produces the described sound. Fast typing is quieter.
Errors are silent. Enter is lower/longer. Backspace is noise-only. Toggle mutes.
Sound cannot be verified programmatically; report as "verified by ear in the harness,
cannot verify in CI."

### M4: Detection signals

- `packages/extension/src/detect/index.ts`: `AgentActivityMonitor` merging signals.
- Implement all 7 signals: `claudeHook.ts` (IPC server), `claudeTranscript.ts`
  (file watcher), `terminalShell.ts`, `taskApi.ts`, `docBurst.ts`, `fsWatch.ts`,
  `hostProbe.ts`.
- Wire the monitor to the offer governor, then to the panel reveal.
- The full detection → 25s wait → offer → reveal → drill lifecycle works.

**Proof:** In VS Code with the extension loaded, opening a terminal and running a
long command triggers detection after 25s. The panel reveals on hotkey. `agent:end`
dims but doesn't close. The detection log command shows signal activity.

### M5: Claude Code hook

- `packages/hook/hook.cjs`: single CommonJS file, reads stdin with 50ms cap, writes
  one JSON line to the IPC socket, exits 0 always.
- `packages/extension/src/hook-installer.ts`: merge-not-clobber write of
  `~/.claude/settings.json`, backup, abort on malformed.
- First-run "[Enable]" button wired to `hook:install` message.
- Test suite asserting exit 0 and empty output under every failure mode.

**Proof:** `packages/hook/test/hook.spec.ts` passes: exit 0 with no listener, malformed
payload, closed stdin, unwritable socket. Installer test shows merge against fixture
files including a malformed one.

### M6: Packaging

- `package.json` extension manifest: `engines.vscode: ^1.93.0`, no proposed APIs,
  activation event `onStartupFinished`, contributes views/commands/keybindings.
- `.vscodeignore` excludes sources, tests, harness, reference, node_modules.
- `pnpm package` runs `vsce package` and produces a VSIX under 2MB.
- Install and activate in VS Code. First-run auto-reveal works.
- Test in at least one of Cursor/Windsurf/Antigravity if available.

**Proof:** `pnpm package` produces a VSIX. `ls -la` shows size under 2MB. The VSIX
installs in VS Code and the panel auto-reveals with a drill on first run.

### M7: Perf test and visual verification

- `tests/perf/typing.spec.ts`: Playwright drives 600 keystrokes at 140wpm into the
  harness with 4x CPU throttle. Asserts p95 < 16.7ms, zero > 33ms, zero forced
  reflows, reveal p95 < 100ms, bundle < 40KB gzipped.
- `tests/visual/idle.spec.ts`: screenshot diff of idle screen, light and dark.
- Screenshots captured to `docs/shots/`.
- Written pass through the forbidden list.

**Proof:** Perf test passes with actual numbers reported. Screenshots in `docs/shots/`
show idle and mid-drill in dark, light, and HC themes. Forbidden-list audit passed.
